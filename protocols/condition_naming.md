# 条件命名口径（2026-11-18 起）

> 目的：避免把“我们自己写的近似实现”叫成作者的方法。表格用论文名称；括号里保留跑格 id 便于追溯。

| 跑格 id | 论文/报告里写 | 是什么 | 能不能叫作者方法 |
|---|---|---|---|
| `none` | 不剪枝 | 基线 | — |
| `avtp` | AVTP | 作者代码（`zry13/AVTP`） | ✅ |
| `avtp_equal` | AVTP 打分 + 每图等额 | 作者打分 + 我们改的分配 | 只能叫“AVTP 打分的等额变体” |
| `sieve` | **等额配额 + 注意力（ours）** | 我们写的：每图等额 + 未剪枝前向的注意力 | ❌ 不是 SIEVE |
| `sieve_random` | **等额配额 + 随机（ours）** | 我们写的：每图等额 + 图内随机 | ❌ 不是 SIEVE |
| `sieve_full`（未来） | SIEVE | 完整实现前置池化 + 多阶段 + 图内合并后 | ✅ 才能叫 SIEVE |

## 引用纪律

只要提到 `sieve` 或 `sieve_random` 的数据，必须同时写出：

> “等额配额 + 注意力/随机（ours，非 SIEVE；缺前置池化、多阶段、图内合并）”

不能只写 `sieve`，也不能把它和 AVTP 并列成“两个方法”。

## 为什么

`src/pruning/sieve.py` 只复现了 SIEVE 的**分配规则**（每图等额）和注意力选择；
没有前置池化、没有 S(N) 多阶段、没有图内合并。把它叫 SIEVE 会高估复现完整度。
详细差异见 `results/archive/2026-11-18_stage1_attribution/ERRATUM.md`。
