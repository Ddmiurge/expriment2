# 勘误：本报告里的 `sieve` / `sieve_random` 不是 SIEVE

原始报告：[`2026-11-18_stage1_attribution_report.md`](2026-11-18_stage1_attribution_report.md)。

## 问题

报告表格里的两个条件：

- `sieve`
- `sieve_random`

**都不是 SIEVE 作者的方法。** 它们是本仓库自己写的：

| 报告里的名字 | 实际是什么 | 论文里应写 |
|---|---|---|
| `sieve` | 每图等额配额 + 我们的注意力选择 | **等额配额 + 注意力（ours，非 SIEVE）** |
| `sieve_random` | 每图等额配额 + 图内随机 | **等额配额 + 随机（ours）** |

我们的实现与 SIEVE 的差距：

1. **没有解码器前的平均池化**；用第 0 层剪枝近似。
2. **没有后半层多阶段选择**（S(N)=clip(N,2,4)）；只做一次选择。
3. **没有图内合并**（丢掉的 token 并进同图最相似幸存者）；直接丢。
4. 注意力取自一次**未剪枝**前向的最后一个 prompt token，不是剪枝过程本身。

## 哪些结论仍可用，哪些不能用

**仍可用（但改名字）**：

- `eq_attn` vs `eq_random` 的 −7.5pp：两者都是每图等额、同预算，只换图内选 token。
  这是“**我们的注意力选择** vs 随机”的对照，不是“SIEVE 的注意力 vs 随机”。

**不能这样写**：

- 不能把 `sieve` 写成“SIEVE”，也不能写“SIEVE vs AVTP”。
  只能写“等额配额 + 注意力（ours） vs 自适应配额 + AVTP 打分”。

**范围收窄**：

- “打分信号没有可检出作用”只能限定为“我们的注意力实现没有”；
  不能推广成“SIEVE 的注意力没有”。

## 处置

- 这两个条件的结果**保留作探索性对照**，但不进入论文对 SIEVE 的引用。
- 任何后续讨论/文档引用 `sieve` 或 `sieve_random` 时，必须同时写明：
  **“等额配额 + 注意力/随机（ours，非 SIEVE；缺前置池化、多阶段、图内合并）”**。
- 如果要把它叫作 SIEVE，必须先实现完整的三块；在此之前，名字不能是 SIEVE。
- 命名映射见 `protocols/condition_naming.md`。
