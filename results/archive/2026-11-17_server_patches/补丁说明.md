服务器按 README 规定只做「只读消费者」，但阶段 0 实测暴露出两处必须改代码才能跑通的地方。
本目录记录服务器上的临时改动，**请把 patch 合入 Mac 侧 `expriment2` 仓库后推送**。

## 1. `2026-11-17_judge_nothink.patch`（必须合入）

**问题**：`src/eval/judge.py` 调 `apply_chat_template` 时没有关闭思考模式。
Qwen3-8B 默认开启 thinking，而判官只给 `max_new_tokens=8`，8 个 token 全被
`<think>\nOkay, let's see.` 吃掉，正则找不到 0–3，抛：

```
ValueError: 判官没输出 0–3："<think>\nOkay, let's see."
```

**改法**：传 `enable_thinking=False`（Qwen3 的 chat template 原生支持，与本机
容器 `bindguard-qwen3-8b` 用的 `qwen3_nothink.jinja` 是同一套思路）。
用 `try/except TypeError` 包裹，换不支持该参数的模型时自动退回旧行为。

**应用**：
```bash
cd <repo>
git apply /home/huangqixu01/server_patches/2026-11-17_judge_nothink.patch
```

## 已知的坑（写给下一位）

- `apply_avtp_patch.py --check` **只认 instrumented 标记**，看不到 `--mode original`
  留下的补丁。若 SM0.3 中途崩溃，文件会停在 original 状态且显示「未打补丁」；
  此时直接 `--mode instrumented` 会叠成两份 `img_start_pos` → `SyntaxError:
  keyword argument repeated`。**正确做法**：先 `--revert`（从
  `.multi_image_orig` 备份恢复）再选模式重打。
- `CUDA_VISIBLE_DEVICES` 会重排可见卡编号：设 `CUDA_VISIBLE_DEVICES=1` 后，
  物理 1 号卡是逻辑 `cuda:0`。`env/paths.yaml` 的 `device` 必须写 `cuda:0`，
  否则报 `CUDA error: invalid device ordinal`。
